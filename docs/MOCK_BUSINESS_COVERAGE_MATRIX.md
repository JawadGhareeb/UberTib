# UperTib Patient Mock Business Coverage Matrix

> Scope: business behavior and mock/state coverage only. This document intentionally does **not** score theme, colors, spacing, typography, responsive quality, animation quality, or visual polish.
>
> Source of truth: `UperTib-Docs/docs/ux/04-specs/SCREEN_SPECS_PATIENT_01.md`, `SCREEN_SPECS_PATIENT_02.md`, `SCREEN_SPECS_PATIENT_03.md`, `docs/ux/01-foundation/USER_FLOWS.md`, and the linked functional requirements.
>
> Evaluation format: **Expected business behavior → Expected displayed data → Mock data exists? → Flow exists? → State transitions represented? → Result**.

## Result definitions

- **Complete** — the current mock has the core displayed data, reachable flow, and the governing transition states needed to exercise the screen's principal business behavior.
- **Partial** — the screen and main happy path exist, but one or more governing data variants, deadlines, recovery paths, or state transitions from the spec are still missing.
- **Missing** — the principal business behavior or required mock data is not represented.

## Current audit result

**47 / 47 patient screens are Complete for mock-level business coverage.**

This means the current mock set contains the core displayed data, reachable patient flow, and governed transition states needed to exercise the documented patient behavior. It does **not** mean backend/API integration is complete; authoritative responses are represented as explicit mock scenarios where a real backend would eventually drive the transition.

## Current high-risk flows now explicitly covered

- Booking alternative proposal remains unconfirmed.
- Alternative decline/expiry closes the request without patient penalty.
- Stale alternative deep links cannot still accept/decline after expiry.
- Confirmed booking can enter `ELIGIBILITY_REVIEW`, recover to confirmed, or cancel without patient penalty.
- Treatment-plan amendment shows previous accepted version, reason, changed line and price delta before acceptance.
- Accepted financial terms expose the governing immutable snapshot fields instead of only a total.
- Protection claim entry is gated by accepted-snapshot entitlement.
- Review submission enters verification-pending before publication.
- Claim decision exposes source, reason, effect and governing policy without implying UperTib moved money.
